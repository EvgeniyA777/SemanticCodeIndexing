# Pinned Java SCIP toolchain (plans/018 Stage 4, ADR-046).
#
# Format: <groupId>:<artifactId>:<version> <sha256-of-jar>
#
# Every jar is fetched from Maven Central and its digest verified before use, so
# an install either matches this pin exactly or fails closed. Bumping a version
# means replacing its digest here in the same commit; a fixture regenerated with
# a different toolchain would otherwise silently disagree with a committed
# golden.
#
# Why these artifacts:
#   semanticdb-javac    javac compiler plugin; emits .semanticdb next to a normal
#                       compile. Self-contained (shaded protobuf).
#   scip-semanticdb     converts .semanticdb -> .scip. This is the whole reason
#                       the heavy `scip-java` Scala CLI (coursier + an embedded
#                       Kotlin compiler) is NOT used: the conversion is a small
#                       Java library with three dependencies.
#   semanticdb-java     SemanticDB model classes used by scip-semanticdb.
#   scip-java-proto     Sourcegraph's own generated SCIP protobuf classes. Note
#                       these live in package `com.sourcegraph`, distinct from
#                       semidx's vendored `scip.Scip`, so nothing collides.
#   protobuf-java(-util) + gson + guava
#                       protobuf runtime required by scip-java-proto and by
#                       ScipWriter's JSON output path. Pinned at 3.25.1 to match
#                       the version semidx already resolves via gRPC, even though
#                       scip-semanticdb declares 3.15.6 — this toolchain runs as
#                       an external process and never joins the semidx classpath,
#                       so the two cannot conflict.
